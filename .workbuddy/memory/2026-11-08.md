## Token 看板：积分口径与展示修正

起因：用户反馈「积分消耗不对、右侧会话名不对、希望显示模型名、所有 token 处都要配积分」。

三个根因（都不是"算错"，是口径和不显示）：

1. `aggregate.credits()` 的 `mapped_ratio` 是"积分行对齐转录的比例"，被当成覆盖率显示 →
   真实 4% 覆盖被读成 100%。改为 `coverage = 有积分记录的请求数 / 全部请求数`（实测 48%），
   新增 `reqs / reqs_covered / sessions_without_credit`。
2. `sessions_meta.title` 只来自 `workbuddy.db` 的 `sessions` 表，且带 `deleted_at IS NULL`；
   不在表里的会话标题为空 → 前端退回 `session_id.slice(0,8)` 显示成八位十六进制。
   现在回退链：`sessions_meta.title` → `accounts.title` → 项目显示名 → `未命名会话`。
   `credit.py` 读 `sessions` 时也去掉了 deleted_at 过滤。
3. 没有积分记录被显示成 `0.00`，看起来像在免费烧。改为 `—`，并标注 `x/y 轮有记录`。

其他：`credit_json` 解析加 `_flatten_credits` 兼容非裸数字结构（原来会静默丢分）；
新增 `credit_reqs / credit_days / credit_hours`、`series[].credit`、`heat[].credit`、
`top_sessions[].model`；前端所有 token 显示点全部配了积分（柱状图右侧两段 rich label、
axisLabel 双行显示会话名+模型）；轮均/日均积分分母改为"有积分记录的轮/天"。

验证方式：Chrome headless 截图（`--headless=new --screenshot`）比对 1400px 与 430px 两种宽度。

## 第二轮：会话排行排版

用户指着「会话消耗 TOP 5」说排版有问题。根因：ECharts 的 category 轴标签在承载两行文字时，
整块按首行基线锚定，标签看上去属于上一根柱子；同一面板内实测行距 33px / 21px 混着来，
lineHeight / verticalAlign 都调不稳。彻底改为 HTML 行布局（`#sessRank`）：

- `.rank` 固定行高 + `justify-content: space-evenly`，剩余空间均分。
- 卡片高 → 两行（名称+模型 / 条形+数值）；矮 → `.rank.compact` 单行
  （`display: contents` 让内部 span 直接参与行内 flex，模型名不被压缩、只让会话名省略）。
- 阈值 32px/行，`ResizeObserver` 实时切换。
- 条形用固定轨道 + 定宽数值列，各行轨道等宽，长度才可比。

排查手段：`--dump-dom` + 临时把布局尺寸写进 `document.title`（查完即删）。

遗留：窄屏 ≤430px 顶栏账号分段控件横向溢出（旧问题）；改动未 commit。
