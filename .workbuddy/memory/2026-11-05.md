## 修复：四个账号在看板上显示同一个名字

- 现象：账号按钮、饼图、切号时间线里 4 个账号全显示「土豆一挖一麻袋」，无法区分。
- 根因：上一版 `config.ACCOUNT_ALIASES` 只配了 `{"default": ...}`，`aggregate._short()` 把它当所有账号的兜底名，4 个不同 user_id 全落到同一字符串。库里真实有 4 个 user_id：`befe3a40`(63 会话)、`76667167`(8)、`5ba9f020`(4)、`6840d741`(2)。
- 修复原则：不存在「所有账号共用的兜底名」。未命名账号用 `ACCOUNT_NAME_TEMPLATE = "账号 {short}"`（带 UUID 前 8 位，天然唯一）；`__none__` 只用于未归属；显式别名按完整 UUID 或前 8 位匹配。
- 改动文件：`config.py`（别名语义 + 模板 + 本机 4 个短码注释）、`aggregate.py`（重写 `_none_label`/`_short`，新增 `Aggregator._labels()`/`_label()`：按库内真实 uid 集合做重名去重、2 秒缓存，5 处输出统一走 `_label`）、`web/app.js`（回退名带短码、renderAcct 的 key 纳入 short 以便改昵称后刷新）、`tools/selftest.py`（新增 [16] 共 8 项）、`README.md`（两处说明同步）。
- 验证：12 个 .py 语法通过；selftest 57 项全通过（含手动重名、旧 default 配置回归）；用真实 `index.db` 的副本跑 `AGG.accounts()` → 4 个账号 4 个不同名字，`period("7d").by_account` 标签一致。
- 取舍：本地状态文件属受保护数据，未读取昵称；真实昵称由用户按需填进 `config.ACCOUNT_ALIASES`。

## 修复：WorkBuddy 项目空间改名后看板不更新

- 现象：在 WorkBuddy 里改项目空间名称，看板仍显示首次创建时的目录名。
- 根因是双重的：① 数据源错 —— `aggregate.py` 两处项目标签用 `os.path.basename(cwd)`，而显示名存在 `~/.workbuddy/workspace-display-names.json`（`workspaces[path].displayName`），改显示名不动磁盘目录；② 版本信号缺失 —— 该文件不写 index.db，`seq` 不涨，导致 `_ver()` 缓存不失效、SSE 也不推。
- 改动：`config.py` 新增 `WORKSPACE_NAMES_PATH`；`aggregate.py` 新增 `workspace_stamp / workspace_names / _display_name / _project_label`（按 mtime+size 缓存、加锁、半截 JSON 保留旧值、逐级向上匹配工作区根），两处标签改用它，`_ver()` 纳入显示名版本，新增 `workspace_version()`；`server.py` 的 `broadcast_loop` 检测版本变化后 `STORE.bump()` 触发 SSE；`tools/selftest.py` 新增 [17] 共 7 项；`README.md` 说明显示名来源。
- 优先级：WorkBuddy 显示名 > 目录名 > 索引编码名。真实数据中 `个人开发→余电开发`、`电脑修复专家→通用助手`，未配置的回退目录名（AI-Work / Study / 宝桥实业气体分公司 / WorkBuddy实时token看板）。
- 验证：12 个 .py 语法通过；selftest 64 项全通过；真实库副本模拟改名后 `period.by_project` 与 `breakdown` 立即变；重启服务（pid 32220）后 `/api/bundle` 实测显示新名字。
- 生效时效：改名只动 json，`broadcast_loop` 每 TICK(1.5s) 检测 mtime 并 bump，前端 SSE 收到新版本即重拉；即使无 SSE 客户端，`_ver()` 也会让下次请求重算。
